This exercise demonstrates how a browser can use WebRTC for sending video stream
to a peer browser, both browsers can be open in two computers connected with a link
and not necessarily internet enabled.

The page 'Assistant Director' (AD) initiates connection generating 'offer' (WebRTC
concept) that has to be communicated to the peer computer. For the instructional
purpose, I do not engage in an http server that should be available to both computers
(typically WebSockets are used to the purpose); instead, I programmatically print out
this 'offer' in stringified form in the text control. A learner can copy the content
of this control to the clipboard, paste it to the text document and send the doc to
the other computer via mail, messenger or shared network folder.

In the peer computer, the user opens the page 'Cameraman' in the browser and paste
the offer to a dedicated control. To make the process easier, I embedded the buttons
"Copy 'offer'/'answer' to clipboard. The browser readily copies to clipboard, but
warns when you try to paste a clipboard content to the page programmatically, so it
is for the user to paste offers/answers to target controls. The workflow logic is
hopefully clear from the webpages' layout and labels, the logic in javascripts can
also help: anyway, the purpose is to deliver WebRTC APIs and tricks, so the user
should examine the sources.

The clipboard exchange is handy when two browsers are on the same computer. So the
user can first examine the-same-host scenario, and then verify that the different-host
scenario also works. I tested this scenario with a WSL2-to-Windows host experiment,
the clipboard is common for both browsers in this case.

For a moment, the connection can be established and the user can verify the operation
with the 'chat' controls. The next step is to transmit the stream generated by
Cameraman's canvas to the AD computer.

If physically differnet, both computers used in this exercise must be in a common
local network!
